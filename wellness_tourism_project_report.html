Wellness Tourism MLOps Project Report

Visit with Us — Wellness Tourism Package Purchase Prediction

This project develops an automated machine-learning workflow to predict whether a customer is likely to purchase the Wellness Tourism Package before outreach.

Approach

The source dataset was registered and accessed through the Hugging Face dataset repository. Data preparation removed the identifier fields CustomerID and the exported CSV index, standardized missing values, and created stratified training and testing datasets using a fixed random seed.

A scikit-learn pipeline performs numerical imputation, categorical imputation, one-hot encoding, and Random Forest classification. Grid-search cross-validation was used to tune the model, while MLflow records the selected parameters and evaluation metrics.

Deployment and MLOps

  • Dockerfile: defines a Python 3.11 Streamlit container on port 7860.
  • Streamlit app: collects customer inputs into a pandas DataFrame and loads the registered model from Hugging Face.
  • Dependencies: are listed in requirements.txt.
  • Hosting script: uploads the application files to a Hugging Face Space.
  • GitHub Actions: automates dataset registration, data preparation, training, evaluation, model registration, and optional deployment.
  • Continuous integration: the workflow runs on pushes to the main branch and supports manual execution.

How the Implementation Was Completed

1. Data registration and preparation

The original tourism.csv file was registered in the Hugging Face dataset repository. The preparation script downloads the registered file, cleans column names, removes CustomerID and the unwanted exported index, converts the target column to an integer, and handles invalid target rows. A stratified 80/20 split is then saved as train.csv and test.csv and uploaded back to the dataset repository.

2. Model training and registration

The training job loads the train and test files, separates the target ProdTaken, and builds a reusable scikit-learn pipeline. Numeric columns use median imputation; categorical columns use most-frequent imputation followed by one-hot encoding. A Random Forest classifier is tuned with grid-search cross-validation over tree count, depth, and minimum leaf size. ROC-AUC is used to select the best configuration.

The selected parameters, cross-validation score, accuracy, ROC-AUC, and classification report are saved to metrics.json. The complete fitted preprocessing-and-model pipeline is serialized as model.joblib and uploaded to sprd12/RandomForest. MLflow is used during training to record the tuned parameters and evaluation metrics.

3. Streamlit prediction application

The Streamlit application presents a customer-input form for the relevant demographic, travel, income, contact, and pitch attributes. When the user submits the form, the values are placed into a one-row pandas DataFrame with the same feature names used during training. The app downloads model.joblib from the public Hugging Face model repository using hf_hub_download, loads it with Joblib, and returns the predicted purchase probability. The model is cached so it is not downloaded again on every interaction.

4. Docker configuration

The Dockerfile starts from a lightweight Python 3.11 image, installs the dependencies from requirements.txt, copies the Streamlit application, exposes port 7860, and starts Streamlit on 0.0.0.0. This makes the application compatible with the container-based runtime used by Hugging Face Spaces.

5. Hosting and CI/CD

The hosting script uses the Hugging Face API to create a Docker Space and upload app.py, Dockerfile, and requirements.txt. The GitHub Actions workflow runs four dependent stages: source-data registration, data preparation, model training/model registration, and optional Space deployment. Hugging Face authentication is supplied through the HF_TOKEN GitHub secret, so credentials are not stored in the code. The dataset and model repository IDs are configured as sprd12/Great_Learning and sprd12/RandomForest.

Deployment Limitation

The application and deployment configuration have been fully prepared, and a Hugging Face Space has been created. However, executing the Python-based Streamlit/Docker deployment required paid or separately enabled Space hardware/configuration. Consequently, the executable deployment assets remain available in GitHub and the Space provides the project hosting location, while the final runtime deployment is subject to Hugging Face billing/configuration.

This limitation is external to the implementation. The Dockerfile, Streamlit application, Hugging Face model-loading logic, dependency file, and hosting script are complete and ready to run once the required Space configuration is enabled.
